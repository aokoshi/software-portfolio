# Архитектура и решения

[← На главную](../README.md)

Проекты независимы: отдельные точки запуска, зависимости и хранилища. Репозиторий объединяет их для удобства просмотра, общего CI и документации.

| Проект | Разделение ответственности | Практический пример |
|---|---|---|
| Дело | `dist` → HTTP API → бизнес-правила и авторизация → SQLite | Заказ и первое сообщение записываются в одной транзакции |
| StockFlow | `public` → `Inventory.php` → PDO → InnoDB | Блокировка строки запаса защищает последнюю единицу при конкурирующих заказах |
| FocusDesk | WPF App → Core → SQLite | Монотонный таймер не зависит от изменения системных часов; состояние сохраняется отдельно от интерфейса |
| Светолесье | WPF Game → Core, отдельно AudioForge | Правила боя и миграции JSON проверяются без прохождения игры вручную |
| Сайт игры | Статические страницы, CSS, DOM-события | Локальные ресурсы и небольшие интерактивные компоненты без сборщика |
| CampusMate | React Native → функции domain → storage | Проверка пересечений расписания и средневзвешенных оценок независимо от экранов |
| PocketBudget | React Native → функции domain → storage | Целые тиыны исключают накопление ошибок дробного представления денежных сумм |

## Компромиссы

WPF ограничивает настольные приложения Windows. Мобильные проекты повторяют небольшие общие компоненты, чтобы каждый можно было запускать отдельно. Локальное хранение упрощает использование, но не даёт облачной синхронизации. В Дело сообщения обновляются опросом; в StockFlow каталог рассчитан на небольшой объём демонстрационных данных.

## Дальнейшее развитие

Возможные следующие задачи: уведомления и синхронизация мобильных приложений, пагинация больших каталогов StockFlow, восстановление пароля в Дело, установка desktop-приложений и ручное тестирование доступности. Эти возможности пока не заявлены как реализованные.
