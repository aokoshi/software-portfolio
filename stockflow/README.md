# StockFlow

Локальная система складского учёта для магазина компьютерных комплектующих. Учебный проект для портфолио: PHP 8.2, MariaDB/MySQL (InnoDB), PDO, JavaScript, HTML и CSS. Без внешних библиотек и этапа сборки.

## Возможности

- Авторизация и три роли: администратор, менеджер, кладовщик.
- Каталог: артикул, категория, поставщик, закупочная и продажная цены, минимальный остаток; поиск и фильтры.
- Несколько складов; поступление, списание и перемещение товара.
- Заказы из нескольких позиций: резервирование, отгрузка и отмена.
- Журнал движений с периодом, складом, типом операции и страницами.
- Обзор запасов, предупреждения о низком остатке и отчёты.
- Создание сотрудников и журнал действий администратора.

## Запуск на Windows с XAMPP

1. Запустите **MySQL** в XAMPP Control Panel. Для указанного ниже способа Apache не требуется.
2. Откройте PowerShell в `<папка репозитория>\stockflow`.
3. При первом развёртывании создайте схему и демонстрационные товары:

```powershell
& C:\xampp\php\php.exe scripts/install.php --demo
```

Без `--demo` создаются схема и два склада, без товаров. Установщик добавляет демоданные только в пустой каталог и не создаёт пользователей.

4. Запустите `start.bat` двойным щелчком либо выполните:

```powershell
& C:\xampp\php\php.exe -S 127.0.0.1:8081 -t public public/router.php
```

5. Откройте **http://127.0.0.1:8081**. При первом запуске создайте администратора; в дальнейшем входите в свой аккаунт. Сотрудников добавляет администратор в разделе «Команда».

Если порт 8081 занят уже работающим StockFlow, просто откройте страницу. Для остановки сервера используйте Ctrl+C в его окне.

## База данных

Настройки по умолчанию соответствуют локальному XAMPP: `127.0.0.1:3306`, база `stockflow`, пользователь `root`, пустой пароль. Если у вашего MySQL другие настройки, создайте `config.local.php` рядом с `config.example.php`:

```php
<?php
return ['username' => 'your_user', 'password' => 'your_password'];
```

Также поддерживаются переменные окружения `STOCKFLOW_DB_HOST`, `STOCKFLOW_DB_PORT`, `STOCKFLOW_DB_NAME`, `STOCKFLOW_DB_USER`, `STOCKFLOW_DB_PASSWORD`. Значения из `config.local.php` имеют приоритет. Этот файл и файлы сессий исключены из Git.

Данные хранятся в MySQL XAMPP, а не в файлах проекта. При работающем Apache базу можно просматривать через phpMyAdmin. Для резервной копии стандартной локальной конфигурации:

```powershell
& C:\xampp\mysql\bin\mysqldump.exe -h 127.0.0.1 -u root --single-transaction --result-file=stockflow-backup.sql stockflow
```

При установленном пароле добавьте `-p`, чтобы ввести его отдельно. Храните копию базы и исходники также на другом носителе или в подходящем удалённом хранилище.

## Роли

| Действие | Администратор | Менеджер | Кладовщик |
|---|---|---|---|
| Просмотр каталога, остатков, заказов и отчётов | Да | Да | Да |
| Создание и изменение товаров | Да | Да | Нет |
| Создание и отмена заказов | Да | Да | Нет |
| Поступление, списание, перемещение, отгрузка | Да | Нет | Да |

## Устройство проекта

- `public/` — единственная публичная папка: интерфейс, API и маршрутизатор локального сервера.
- `src/Inventory.php` — бизнес-правила и транзакции складских операций.
- `src/bootstrap.php` — подключение, валидация, права и общие функции.
- `database/schema.sql` — таблицы, индексы, внешние ключи и ограничения.
- `scripts/install.php` — установка схемы и необязательные демоданные.
- `tests/` — проверки бизнес-правил и HTTP.
- `storage/` — локальные сессии, не включаются в репозиторий.

Связи: товары и склады соединяются таблицей `stocks`; заказ относится к складу и сотруднику и содержит `order_items`; каждое изменение запаса отражается в `movements`. `audit` содержит действия пользователей, `commands` — результаты повторяемых команд.

Доступное количество = физический остаток − резерв. Резерв не меняет физический остаток; отгрузка уменьшает оба значения; отмена снимает резерв. Нельзя списать или переместить зарезервированный товар.

Каждая складская команда выполняется в транзакции. Строки остатков блокируются через `SELECT ... FOR UPDATE`, чтобы два заказа не получили одну последнюю единицу. Перемещение меняет оба склада атомарно. Цена и название позиции сохраняются в заказе на момент его создания. Повтор команды с тем же ключом и содержимым возвращает исходный результат без второго списания.

Пароли хешируются средствами PHP. API проверяет роли, CSRF-токен, входные данные и срок сессии. SQL использует параметры PDO. Cookie сессии имеет HttpOnly и SameSite=Strict. Число попыток входа ограничено.

## Проверки

При запущенном MySQL:

```powershell
& C:\xampp\php\php.exe tests/run.php
```

Тест создаёт отдельную случайно названную базу и удаляет её после завершения. Нужны права создания и удаления тестовой базы. Не задавайте фиксированное поле `database` в `config.local.php` для тестового запуска: тест остановится, чтобы не затронуть рабочую базу.

23 проверки охватывают права, резервы, перемещения, отгрузку, отмену, повтор команд, откат заказа из нескольких позиций, сохранение цены, согласованность журнала и два одновременных заказа на последнюю единицу.

HTTP-проверки запускайте на отдельной тестовой установке с уже созданным администратором:

```powershell
$env:STOCKFLOW_TEST_EMAIL='test@example.test'
$env:STOCKFLOW_TEST_PASSWORD='your-test-password'
& C:\xampp\php\php.exe tests/http.php http://127.0.0.1:8082
```

9 проверок: анонимная сессия, защита данных без входа, CSRF, неверный пароль, успешный вход, доступ к данным, запрет повторной первичной регистрации, выход и недействительность завершённой сессии. Они используют отдельную HTTP-сессию.

В браузере дополнительно проверены создание и отгрузка заказа и отсутствие горизонтального переполнения страницы на узком экране.

## Границы первой версии

Цены — целые тенге. Стоимость запасов рассчитывается по текущей закупочной цене; это не бухгалтерский учёт себестоимости по партиям и не расчёт прибыли. Даты фильтров журнала относятся к UTC, время событий отображается в часовом поясе браузера. Данные обновляются после ваших операций; для изменений другого сотрудника обновите страницу.

Пока нет импорта Excel, штрихкодов, возвратов, восстановления пароля и редактирования сотрудников. Каталог и заказы загружаются целиком — текущая версия рассчитана на небольшую демонстрационную базу. Для публикации понадобятся производственный сервер с HTTPS, отдельный пользователь БД, резервное копирование и дополнительные эксплуатационные настройки. Веб-сервер должен открывать только папку `public`, а не корень проекта.

## Демонстрация для портфолио

1. Покажите обзор и товар с низким остатком.
2. Проведите поступление и перемещение между складами.
3. Создайте заказ и объясните разницу между остатком и доступным количеством.
4. Попробуйте списать зарезервированный товар: сервер отклонит операцию.
5. Отгрузите заказ и покажите изменения в журнале.
6. Покажите разграничение ролей и тест конкуренции за последнюю единицу.
