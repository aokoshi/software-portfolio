# Дело — сервис цифровых услуг

Рабочий локальный проект: аккаунты клиентов и продавцов, каталог услуг, заказы и личная переписка. Данные сохраняются в SQLite, а не в localStorage. HTML/CSS/JavaScript, Node.js 24+ и встроенный модуль node:sqlite. Внешние зависимости не нужны.

## Запуск

```powershell
cd <папка репозитория>\delo-services
node server.mjs
```

Откройте http://127.0.0.1:4173. Остановка: Ctrl+C. Не открывайте `dist/index.html` напрямую: аккаунтам и данным нужен сервер. Если доступен npm, также можно использовать `npm start`.

При первом запуске база создаётся автоматически: `data/delo.sqlite`. Каталог сначала пустой. Готовых аккаунтов с общими паролями нет.

1. Зарегистрируйтесь с ролью **Продавец**.
2. В разделе **Мои услуги** создайте предложение: название, описание, категория, цена, срок и один из восьми логотипов сайта.
3. Выйдите и зарегистрируйте второй аккаунт с ролью **Клиент**, используя другой email. Можно открыть другой браузер/приватное окно, чтобы одновременно работать с двумя ролями.
4. Найдите услугу, напишите продавцу или оформите заказ с брифом.
5. Продавец увидит заказ в **Моих заказах**, а переписку — в **Сообщениях**.

## Возможности

- Регистрация с выбором роли, вход, выход и сессия на 7 дней.
- Каталог с поиском по названию, описанию и имени исполнителя, фильтрами по категории, цене и сроку, сортировкой и страницами по 12 услуг.
- «Мои услуги»: создание, редактирование, снятие с публикации и повторная публикация. Собственные изображения и URL логотипов сервер не принимает.
- «Мои заказы» у обеих ролей: бриф, собеседник, цена, срок и фильтр статусов. Цена и срок фиксируются при оформлении и не меняются после редактирования услуги.
- Переписка привязана к клиенту и услуге; повторный заказ использует тот же разговор. Бриф автоматически появляется в чате. Сообщения обновляются раз в 5 секунд, есть счётчик непрочитанных. История загружается порциями по 100 сообщений.
- Обработка ошибок, пустых состояний, защита от повторного создания заказа при повторе того же запроса.
- Адаптивные страницы, нативные диалоги, клавиатурная навигация.

## Статусы заказа

| Текущий статус | Действие продавца | Действие клиента |
|---|---|---|
| Новый | Принять в работу или отклонить | Отменить |
| В работе | Передать на проверку | Обсудить работу в чате |
| На проверке | Общаться в чате | Принять или вернуть на доработку |
| Завершён / отменён | Просматривать историю | Просматривать историю |

## Структура и база

- `server.mjs` — запуск сервера, безопасная раздача только публичных файлов.
- `lib/database.mjs` — схема, индексы, транзакции, категории и допустимые логотипы.
- `lib/auth.mjs` — хеширование паролей, создание и проверка сессий.
- `lib/api.mjs` — JSON API, проверка данных, ролей, владельцев и переходов статуса.
- `dist/index.html`, `dist/app.js`, `dist/styles.css` — интерфейс.
- `tests/marketplace.test.mjs` — интеграционные тесты с отдельной временной базой.
- `data/delo.sqlite` — рабочая база (не включается в Git).

Таблицы: `users`, `sessions`, `services`, `orders`, `conversations`, `messages`, `conversation_reads`. У пользователей есть услуги и заказы; разговор связывает услугу, клиента и продавца. Заказ ссылается на разговор. Внешние ключи включены, запись заказа и первого сообщения выполняется в одной транзакции. SQLite использует WAL.

### Основные адреса API

| Метод и путь | Назначение |
|---|---|
| POST /api/register, /api/login, /api/logout | Управление сессией |
| GET /api/me, /api/meta | Текущий аккаунт, категории и логотипы |
| GET /api/services | Публичный поиск и фильтры |
| POST /api/services | Создание услуги продавцом |
| GET /api/my-services | Все свои услуги, включая скрытые |
| GET /api/services/:id | Карточка услуги |
| PATCH /api/services/:id | Изменение своей услуги или её видимости |
| GET, POST /api/orders | Свои заказы / создание заказа клиентом |
| PATCH /api/orders/:id | Допустимый переход статуса |
| GET, POST /api/conversations | Свои разговоры / начало разговора клиентом |
| GET, POST /api/conversations/:id/messages | Чтение / отправка сообщений |
| POST /api/conversations/:id/read | Отметить доставленные в интерфейс сообщения прочитанными |

Для изменяющих запросов обязательны JSON, совпадающий `Origin` и заголовок `X-Delo-Request: 1`. Авторизация идёт через HttpOnly cookie.

## Защита и границы

Пароли хешируются scrypt с индивидуальной солью; сервер хранит только хеши токенов сессий. Cookie имеет HttpOnly и SameSite=Strict, а в production ещё Secure. Роли, владение услугами и участие в чатах проверяются сервером на каждом запросе. Есть параметризованные SQL-запросы, ограничения длины и частоты запросов, CSP и вывод пользовательского текста с экранированием. База и серверные файлы не раздаются через HTTP.

Это локальный MVP для портфолио. Пока нет платежей, подтверждения email, восстановления пароля, вложений, модерации и административной панели. Email при регистрации сохраняется, но не подтверждается. Роль выбирается один раз. Для эксплуатации в интернете нужны HTTPS, операционные резервные копии и перечисленные функции по требованиям продукта. Поиск по тексту в этой версии выполняется в Node.js для корректной обработки регистра кириллицы; для большого каталога стоит добавить FTS/поисковый движок.

Сервер по умолчанию слушает только `127.0.0.1`. Переменные окружения: `PORT`, `HOST`, `DELO_DB` (путь к базе), `PUBLIC_ORIGIN` (точный внешний адрес сайта), `NODE_ENV=production` (Secure cookie; требует HTTPS). Автоматическая загрузка `.env` не реализована — задавайте переменные в среде запуска.

## Проверка

```powershell
node --check server.mjs
node --check lib/api.mjs
node --check dist/app.js
node --test tests/marketplace.test.mjs
```

Интеграционные проверки охватывают регистрацию, хеши паролей, роли, допустимые логотипы, поиск и фильтры, изоляцию чатов, непрочитанные сообщения, идемпотентность заказов, снимок цены, статусы с доработкой, снятие услуг с публикации, CSRF-проверки, закрытые файлы, постраничную историю, сохранение данных после перезапуска и аннулирование сессии.

Браузерный сценарий проверен на отдельной базе `.sites-runtime/ui-test.sqlite`: регистрация обеих ролей, создание услуги, поиск, заказ, сообщение клиента, принятие заказа и ответ продавца. Рабочая база не заполняется этими тестовыми аккаунтами. При проверке мобильного мессенджера на ширине 390 px горизонтального переполнения нет.

## Резервные копии

Сохраняйте код в своём Git-репозитории. База исключена из Git: для простой резервной копии остановите сервер и скопируйте **всю папку `data`** на другой диск или в резервное хранилище. Не копируйте только основной `.sqlite` при работающем сервере: последние записи могут находиться в WAL. Для регулярных копий без остановки используйте SQLite backup API.

Справочник SQLite для используемого рантайма: https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html
